## 7. Sleep Phase 2 の位置づけ

### 7.1 今回の検討との関係

├── MIGRATION.md       # 改修計画

```

### 7.2 主要な設計決定

1. **インデックス + グラフ構造が本質**
   - ベクトルは手段、識別と関連がコア

2. **再認 vs 想起の分離**
   - 再認: position index で exact match
   - 想起: エッジを辿る or 類似検索

3. **エッジを使った検索効率化**
   - ノード追加時: O(n) で類似度をエッジに記録
   - 検索時: O(隣接数) でエッジを辿るだけ

4. **行き止まり回避**
   - DGエッジを辿ってループ/負例を検知

### 7.3 実装タイミング

```

#### 25×25 論文実験（60 seeds, 500 steps）

| 段階 | max_hops | 成功 | 成功率 | 備考 |
|------|----------|------|--------|------|
| 初回 | 10 | 43/60 | 71.7% | 17シード失敗 |
| リトライ1 | 15 | 51/60 | **85.0%** | +8シード成功 |
| リトライ2 | 25 | 51/60 | 85.0% | 追加効果なし |

**最終失敗シード（9個）**: seed 9, 16, 28, 32, 35, 48, 49, 51, 52
- 全てsteps=500到達（max_steps上限）
- hop数増加では解決せず → steps増加が必要

**考察**:
- **hop数に「最適値」はない** - geDIGは必要な時だけ深いhopを評価するため、上限は大きくても問題ない
- hops=10→15で改善 = 10では評価範囲が不足していたシードがあった
- hops=15→25で変化なし = 15で既に十分な評価ができていた（25が過剰という意味ではない）
- **残り9シードの失敗原因はsteps不足**（hop数ではない）→ steps=1000で改善見込み
- **最終成功率85%**はベースラインとして妥当
