# ARC Prize Roadmap（InsightSpike / geDIG で ARC を狙うための計画）

**Version**: 0.1 (Draft)  
**Date**: 2026-01-29  
**Author**: Kazuyoshi Miyauchi  
**Status**: Proposal

---

## 0. 目的

ARC（Abstraction and Reasoning Corpus）系タスクに対して、**DSL（操作言語）× プログラム探索**を軸にしたソルバを構築し、ARC Prize 相当の評価環境で戦える水準まで引き上げる。

本リポジトリの強みである geDIG（単一ゲージ + AG/DG）を、探索の爆発を抑えつつ「有望な構造編集」を選別・定着させる制御則として統合する。

---

## 1. 前提（要確認）

ARC Prize の「提出形態」「推論時間制限」「外部ツール/LLMの扱い」「学習可否」「スコアリング（pass@1 / pass@N 等）」は年・トラックで変わり得るため、**公式ルールに合わせて本計画を調整する**。

この計画では、以下を想定する：
- 入力は 2D グリッド（色 0–9）
- 各タスクは train の (input, output) 複数ペアと、test の input を含む
- 出力は test input に対する 1 つのグリッド予測
- 目的は「正解一致」の最大化（探索・汎化が本質）

---

## 2. 成功指標（このリポジトリ内の運用指標）

### 2.1 主要KPI
- **Solved@Train**: train ペアを完全再現できるタスク割合
- **Solved@Eval**: held-out（公式dev相当）での正解率
- **Runtime**: 1タスクあたりのP50/P95（CPUのみ想定）
- **Determinism**: seed固定で結果が再現できるか（提出の安定性）

### 2.2 付随KPI（探索品質）
- **Search Budget Efficiency**: 1正解あたりの展開ノード数/時間
- **Generalization Gap**: train-fit と eval の落差
- **Macro Reuse Rate**: 既知マクロが解に寄与した割合

## 3. 開発ロードマップ（段階的に勝ち筋を作る）

### Phase 0: ベースライン整備（評価可能にする）
**狙い**: 「回る」「測れる」「保存できる」状態を最優先で作る。

- ARCデータの取り込み（DLスクリプト or 手動配置 + ローダ）
- 評価ハーネス（split/seed固定、pass判定、集計）
- 最小ソルバ（例: 既知の単純変換のみ、または空実装）でも実行可能に
- 失敗例の保存（task単位のログ、予測出力、再現用コマンド）

**Doneの定義**
- `python .../run_arc_eval.py --split dev` のような1コマンドで一通りの評価が走る
- 結果が `results/arc/...` に記録される

---

### Phase 1: DSL v1 + 列挙探索（「解ける」を作る）
**狙い**: まずは狭いDSLで、解けるタスクを確実に取る。

- グリッド基本操作のDSL v1（回転/反転/トリミング/リカラー/平行移動など）
- 型付きAST（プログラム表現）＋コスト（プログラム長/パラメータ数）
- 列挙探索（BFS/ビーム）＋メモ化（中間結果キャッシュ）
- train-fit の厳密判定（完全一致のみ）

**Doneの定義**
- “定番の簡単ARC” がいくつか解ける（再現可能にログが残る）
- 速度劣化なしにDSL追加ができる構造になっている（OP登録が容易）

---

### Phase 2: Object-centric DSL v2（「抽象」を入れる）
**狙い**: ARCで頻出の「物体」「関係」「規則」を扱えるようにする。

- 連結成分（4/8近傍）・BBox・形状特徴量・重心
- 「物体→操作→再配置→合成」系のDSL拡張
- 複数オブジェクトの対応付け（入力→出力のマッチング仮説）
- 探索の爆発に備えた正規化（同値プログラムの潰し込み）

**Doneの定義**
- 物体抽出が必要なタスクで、train-fit が取れるケースが出る
- 探索ログで「どの仮説が効いたか」が追える

---

### Phase 3: geDIG制御の導入（探索の“自律制御”）
**狙い**: 「探索を深めるべきか」「統合すべきか」を単一ゲージで制御する。

- **ゲージ定義**: `F = ΔEPC_norm − λ·ΔIG_norm` をARC探索に写像
  - ΔEPC_norm: プログラム編集コスト（長さ/演算種/パラメータ）を正規化
  - ΔIG_norm: train-fit 改善（誤差減少/未一致セル減少など）を正規化
- **AG（Attention Gate）**: `g0 > θ_AG` なら探索範囲（深さ/DSL幅）を拡張
- **DG（Decision Gate）**: `min{g0,g_min} ≤ θ_DG` なら仮説（部分プログラム/マクロ）を確定して再利用可能に
- ログを「監査可能」に（g0/g_min の時系列、発火点、採択理由）

**Doneの定義**
- 同一の探索予算でも、geDIG制御ありの方が「解ける/早い」が出る
- DGで確定したマクロが別タスクでも再利用される

---

### Phase 4: 学習/記憶の導入（“蓄積で強くなる”）
**狙い**: 解いた経験が次を速く解く（Wake/Sleep）ループを作る。

- **Wake**: 探索中に得た有効部分プログラム（DG確定）を短期記憶へ
- **Sleep**: オフラインで頻出パターンを圧縮し、マクロ/テンプレとして長期記憶へ
- 近傍タスク検索（類似タスクから初期候補を生成）
- （任意）ニューラル提案器：DSLオペレータ/パラメータを提案する軽量モデル

**Doneの定義**
- 時間とともに「初期候補の質」が改善し、探索が短縮する

---

### Phase 5: 提出品質（再現性・速度・梱包）
**狙い**: “動く”だけでなく、提出物として安定に動く。

- 依存関係の最小化（CPUのみ/サイズ制約に対応）
- deterministic 実行（乱数、並列、キャッシュの固定）
- 入力/出力のI/O仕様を固定（提出フォーマットに合わせる）
- タイムアウト時の挙動（最良候補の返却、フェイルセーフ）

**Doneの定義**
- 提出環境の制約下で、安定して推論が完走する

---

## 4. ファイル/モジュール構成案（最小の追加で始める）

（実装は別紙 `docs/design/arc_prize_spec.md` で定義）

- `src/insightspike/arc/` … ARCソルバ本体
- `scripts/arc/` … データDL・評価・可視化
- `experiments/arc_prize/` … 実験ログ、アブレーション、結果集計
- `results/arc/` … 実行ログ/予測/集計（git管理対象外推奨）

---

## 5. 主なリスクと回避策

- **DSLが足りない**: まずは勝てるDSLを薄く広くではなく「頻出」から順に拡張。未解は失敗ログとして資産化。
- **探索爆発**: 型付け・正規化・キャッシュ・ビーム、そして geDIG で探索深さ/幅を制御。
- **train-fit偏重で汎化しない**: 物体対応・不変量・簡潔性（MDL的）をコストに入れる。マクロの過学習をsleepで剪定。
- **提出制約**: 早い段階からCPU/時間制限を前提に、P95を追う。
