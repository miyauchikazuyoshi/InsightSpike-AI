# 事前登録（Pre-registration）ディレクトリ

このディレクトリは、本プロジェクトの**確証実験の事前登録**を保管する。
運用プロトコルは 2026-07-02/03 の sleep アブレーション 3 連実験
（v1 敗北 → 設計監査 → v2 成立 → v3）で確立された。

## 原則

1. **確証実験は実行前にここへ登録する**。書式は既存ファイルを踏襲:
   主張（+スコープ限定）／事前予測 P1..Pn／反証条件（表）／実験設計（操作は 1 変数・統計は変更禁止）／
   主要指標／既知リスク／凍結手続き／§8 結果（実行前は空欄）
2. **状態遷移**: DRAFT（編集可）→ パイロット実測を §6 に追記 → **FROZEN（著者の明示承認が必要）**
   → 以後は**追記のみ**（本文の書き換え禁止）→ 実行 → §8 に結果を追記（成立でも敗北でも）
3. **解析スクリプトは実験実行前にコミット**する（bootstrap シード固定、判定文言は §3 の言葉を機械出力）。
   実行後の変更は逸脱として記録する
4. **操作チェック（P3）を装置に組み込む**。P3 不成立は「装置の敗北」であり「理論の敗北」と区別する
5. **敗北を記録する**。事後説明による矛盾吸収をしない。予測が外れたら §8 に敗北記録を追記し、
   公開文書（README 等）の主張を実測に合わせて更新する
6. **反証は 2 層**: 実装レベル（この構成が効かない）と概念レベル（事前に切った試行予算の枯渇で撤退）
7. **探索と確証を分離する**: 探索的ランは自由だが、`results/**/_exploratory_*/` に隔離して NOTES を残し、
   確証の prereg の §0 で開示する。探索で使ったシードは確証から除外し、パラメータは探索結果への
   「調整」ではなく原則で固定する
8. **「検出力不足」と「反証」を判定で区別する**（小標本の層別では特に）
