# 事前登録: 迷路 stage-2 — Sleep 単独アブレーション（sleep on/off）

> **日付**: 2026-07-02（実験実施前にコミット）
> **状態**: **FROZEN**（2026-07-02、著者承認） — 以後は追記のみ（本文の書き換え禁止）
> **前提**: v6_perseed（25×25）で成功率 71.9%→95.3%、平均ステップ −41%、エッジ −34% を観測。ただしこれは **10D ベクトル＋sleep 伝播＋カリキュラムを同時に変えたパッケージ効果**であり（baseline n=32 / extended n=64 と標本も非対称）、sleep 単独の寄与は未分離（2026-06-10 監査で指摘された「アブレーション負債」）。
> **実験装置**: `--sleep-propagate {on,off}` フラグを 2026-07-02 に実装（`qhlib/cli.py`, `qhlib/models.py`, `run_experiment_query.py`）。off = Wake1 の生グラフを無変更で Wake2 に継承（報酬伝播なし・孤立ノード除去なし・dim9 は初期値のまま）。9×9 スモークで操作を確認済み: on → 継承 57 ノード全てに `propagated` 属性、off → 継承 140 ノード（生グラフ）で `propagated` 属性ゼロ。

## 1. 主張（検証対象）

> Sleep 相の**値再処理**（Q 学習様の報酬伝播 + 孤立ノード除去 + dim9 同期。**geDIG ゲージ F は一切使用しない**）は、10D ベクトルとカリキュラムを両群で固定した条件下で、**単独で**第 2 エピソード（Wake2）の探索性能を改善する。

（用語注: 本文書では「sleep」を上記の操作的定義に限定して用いる。これは論文 Phase 2 が構想する
F 駆動のオフライン再配線ではなく、その**前駆体 — F 非依存の値固定化**である。構造の再編
（剪定・再配線・merge/split）は行われない。）

### 1.1 スコープ限定 — 本実験は「存在証明」であり「操作方法の検証」ではない

伝播値の readout（Wake2 の行動への反映）は現行実装に **2 経路が同時に存在**する:
(i) dim9 = tanh(propagated) が類似度計算に効く経路（extended モード）、
(ii) `propagated_alpha`（デフォルト 1.0）による行動選択への直接バイアス（適用形はコードパスにより exp 乗算と加算が混在）。
さらに `propagated_mode` (abs/gradient)、伝播パラメータ（γ=0.95, iters=50）、prune（実装済み・既定 OFF）という未検証の設計選択肢がある。

**本実験の操作 `--sleep-propagate off` は伝播値そのものを不在にするため、両 readout 経路が同時に沈黙する。** したがって:
- **P1 成立時に主張できるのは「現行 sleep 一式（デフォルト構成）に荷重がある」まで**。どの機構・どの readout が効いたかは主張しない。
- 機構の分解と選定（readout 経路の単離、γ/iters 感度、prune on/off、abs vs gradient — sleep 設計ノートの完了条件 (b)「重み調整法の選定」に対応）は、**P1 成立を条件とした次の事前登録**で行う。
- P1 不成立の場合、機構選定は無意味となり実施しない（存在しない効果の機構は分解できない）。

### 1.2 Phase 論における本実験の位置（FROZEN 範囲の宣言）

sleep には 3 層の Phase 階層が存在する:

| 層 | 内容 | 本実験との関係 |
|---|---|---|
| **論文 Phase 2**（オフライン全体最適化の構想） | F 駆動の再配線・剪定・統合（min α·GED + β·H + γ·\|E\|）、ヘッブ学習、神経修飾物質 | **範囲外**（将来構想） |
| **graph_persistent_dg**（最小実装） | F 非依存の値伝播 + 孤立除去 + dim9 同期 | **本実験の検証対象** |
| **SPEC §6 実装 Phase 0/1/2** | 最小実装内の実装段階（0/1 の中間検証はスキップされ、2026-07-02 に事後テスト化 → 飽和を発見） | 本実験 = Phase 2 検証項目の 1 ペア |

**FROZEN として検証する範囲は最小実装のみである。著者の言葉で:**

> まだ F は活きていない。環境で定義した正例・負例（goal/novel の正、deadend/blocked/revisit の負）の伝播値が、次エピソードの最適化に寄与するか — このレベルの実験である。

したがって本実験の結果は、成立・不成立いずれの場合も以下には**及ばない**:
1. **F 駆動 sleep**（各編集を F(edit)<0 でゲートする論文 Phase 2 の中核）の有効性
2. **構造再編**（prune / merge / split）の有効性
3. **飽和を修正した伝播**（SPEC 意味論準拠版）の有効性

これらは §3.2 の試行予算の枠内で、それぞれ独立に事前登録して検証する。特に 1（sleep の F 駆動化）は、
飽和修正と並ぶ再設計バリアントの本命候補であり、Sleep-RAG 構想（merge/split を F でゲート）への
接続点でもある。

## 2. 理論の事前予測（sleep 機構が実在の荷重を持つなら成り立つこと）

- **P1（Primary）**: Wake2（eval）ステップ数は sleep-on < sleep-off（同一シード・同一迷路の paired 比較で有意）
- **P2**: Wake2 成功率は sleep-on ≥ sleep-off（25×25 では成功率は天井にない: v6_perseed で eval 95.3% vs baseline 71.9%）
- **P3（操作チェック）**: sleep-on の継承グラフは `propagated` 属性を持ち、sleep-off はゼロ（結果 JSON の `curriculum.per_seed.*.inherited_propagated_nodes` で機械検証）

## 3. 反証条件（外れたら理論側の敗北として記録する）

反証の帰結は**実装レベル**と**概念レベル**の 2 層に分けて事前定義する。本実験 1 回で棄却されるのは実装レベルの主張のみである。ただし「実装が悪かっただけ」を無限の逃げ道にしないため、概念レベルの撤退基準（試行予算）も同時に登録する。

### 3.1 実装レベル（本実験の直接の帰結）

| 条件 | 帰結 |
|------|------|
| P1 不成立（paired 差の CI95 が 0 を含む、または逆方向） | **「現行実装・現行設定の sleep 一式は荷重を持たない」と記録し、v6_perseed の改善（+23.4pt / ステップ −41%）の sleep への帰属を撤回する（カリキュラム・10D ベクトル由来とする）**。この帰属変更は実装の良否と独立に成立する。論文 stage-2 の主張から「sleep の寄与」を撤回し「グラフ持ち越し＋カリキュラムの効果」に縮約する。Sleep-RAG は前提（maze での sleep 効果分離）が満たされないため凍結を継続し、復帰条件を §3.2 の決着に更新する |
| P1 成立だが P2 逆方向（成功率が有意に低下） | sleep は速度と引き換えに堅牢性を損なうと記録し、主張を「ステップ短縮のみ」に縮約する |
| P3 不成立 | 実験装置の故障。結果を無効とし、修理後に再実行（これは理論の敗北ではなく装置の敗北として区別する） |

### 3.2 概念レベル（sleep = オフライン再編の工学的価値）

- **本実験の P1 不成立は sleep 概念の棄却ではない**。棄却されるのは §1.1 のとおり「現行デフォルト構成」の主張である。
- ただし概念を反証可能に保つため、**再設計の試行予算**を切る: P1 不成立の場合、代替実装バリアント（例: SPEC 意味論準拠の伝播・F 駆動化・readout 単離・prune-on・Hebbian 共起系 — sleep 設計ノート完了条件 (b) の候補群）の追加試行は**各回事前登録の上で最大 N 回**とする。
  - **DECISION-1: N = 2 で確定**（2026-07-02、著者承認。現行構成と合わせ計 3 構成）。
- 試行予算が尽きてなお P1 相当が不成立の場合、**maze ドメインにおける sleep 再編の工学的主張を撤回**し、理論ノート `gedig_core_theory_unified.md` §9.6 の棄却条件「迷路で Sleep 相を追加しても Wake-only と性能差がない」の充足として記録する（理論側の敗北記録）。
- 逆に P1 成立の場合、概念レベルは「少なくとも 1 つの実装で荷重が実証された」に更新され、機構選定（§1.1 の (b)）へ進む。

事後説明による矛盾吸収は行わない。予測が外れた場合は本ファイルに「敗北記録」を追記する。
「off 群は孤立ノードのせいで不利だった」等の言い訳を**事後に**導入することは禁止（孤立ノード除去は sleep の仕事の一部であり、その利得は sleep の利得である。伝播と掃除の寄与分解は本実験の範囲外で、別途事前登録の上で `--sleep-propagate-iters 0` により行う）。再設計バリアントの投入は §3.2 の試行予算内で、かつ**新しい事前登録を先にコミットした場合のみ**許される — 本実験のデータを見てから本実験の解釈を変えることとは区別する。

## 4. 実験設計

### 条件（操作は 1 変数のみ）

| | sleep-on | sleep-off |
|---|---|---|
| `--sleep-propagate` | `on` | `off` |
| それ以外の全フラグ | 完全に同一 | 完全に同一 |

### 共通設定（v6_perseed の COMMON_ARGS + extended を両群に固定）

```
--maze-size 25 --max-steps 500 --max-hops 15 --sp-cand-topk 5
--curriculum-warmup-steps 500 --lambda-weight 0.01 --steps-ultra-light
--vector-mode extended
```

- 辞書ベースの sleep 誘導（sleep_plan / sleep_q、`--sleep-guide` デフォルト = override）は**両群で共通に動作**する。本実験が分離するのは**グラフ報酬伝播（graph-persistent DG）の寄与のみ**。
- **設計計画との対応**: `graph_persistent_dg/SPEC.md` §6 Phase 2 は 4 条件アブレーション（グラフ伝播 / 辞書β / 両方 / なし）を構想している。本実験はそのうち**「両方 vs 辞書βのみ」の 1 ペア**であり、README の最優先実験定義「sleep 伝播のみ切替」と一致する。残る 2 条件（伝播単独・両方なし）は本実験の結果を見て別途事前登録する（特に §6 の床効果リスクが現実化した場合、辞書βを切った「伝播単独 vs なし」が次の切り分けになる）。
- 報酬テーブルは実装値（goal +1.0 / novel +0.2 / revisit −0.4 / deadend −1.0 / blocked −1.0）を両群共通で使用。wake 中に dim8（生 reward）へ同期されるため、**off 群でも生報酬情報はベクトルに保持される** — sleep が加えるのは伝播値（dim9）・孤立ノード除去のみであり、これが分離対象の操作である。
- シード: **0–29（n=30、paired）**。シードが迷路と初期条件を決定するため、同一シードの on/off が対応のあるペアを成す。
- 実行順: シードごとに on → off を続けて実行（環境ドリフトの群間偏りを防ぐ）。
- 実行スクリプト: `experiments/maze/run_sleep_ablation.sh`（run_v6_perseed.sh の 2 条件版、per-seed 実行でメモリ蓄積を回避）。

### 統計（変更禁止）

1. **Primary**: Wake2（eval）ステップ数の paired 差。Wilcoxon signed-rank（両側 α=0.05）+ paired bootstrap CI95。
   - **打ち切りの扱い（事前定義）**: 失敗シード（500 ステップ内にゴール未達）の eval ステップ数は **steps=500（上限値）として全 30 ペアで主解析**を行う。感度分析として「両条件とも成功したペアのみ」の解析を併記する。主判定は前者。
2. Secondary: Wake2 成功率の McNemar 検定（正確二項）、Wake2 最終エッジ数（`avg_edges`）、継承グラフのノード・エッジ数。
3. 多重比較: 主検定は P1 の 1 つのみ。P2 以下は探索的と明記。

**解析コードの事前固定**: 上記の統計は `experiments/maze/analyze_sleep_ablation.py` として実装し、**実験実行前にコミット**する（bootstrap 乱数シード 20260702 固定、判定は §3 の文言を機械的に出力）。合成データで打ち切り・欠損・操作チェックの全経路を検証済み。実行後にこのスクリプトを変更する場合は逸脱として記録する。

## 5. 主要指標（変更禁止）

1. **Primary**: 25×25・n=30 paired における Wake2 ステップ数の sleep-on − sleep-off 差（Wilcoxon p 値と bootstrap CI95）
2. Secondary: Wake2 成功率差（McNemar）、エッジ数差、（参考）warmup 側の指標に群差がないことの確認（warmup は sleep 前なので差があってはならない = 追加の操作チェック）

## 6. 既知のリスク

- **【FROZEN 前の重要発見 2026-07-02】伝播実装は SPEC の設計意図を満たしていない**。
  スキップされていた SPEC Phase 1 検証（伝播値の符号構造確認）をテスト化した結果
  （`experiments/maze/test/test_sleep_propagate_semantics.py`）:
  - 無向グラフ上の `propagated(n) = reward(n) + γ·max(neighbor)` は相互強化で発散的に膨張し
    （固定点 ≈ reward/(1−γ)）、**dead-end を含む全ノードが正**になる（goal 到達エピソードで
    dead_end ≈ +9.9、goal 側 ≈ +13; goal 未達でも全ノード +4.7〜6.0）。
    SPEC §3.3 の「dead-end 側が負になり回避される」という物語は**現行実装では成立しない**
    （設計意図は strict xfail として固定済み）。
  - **dim9 = tanh(propagated) は両ケースで飽和**（>0.999）し、識別信号としてほぼ機能しない。
    生き残る信号は**順序**（goal 側 > dead-end 側）のみで、これは α 直接バイアス
    （特に exp 乗算経路の実質 argmax 化と gradient モード）でのみ実質的に読み出される。
  - **本実験の解釈への影響（事前登録）**: 本実験はあくまで「**v6_perseed で実際に走った現行実装**」
    の寄与の検証であり、この歴史的帰属の決着としての価値は乖離発見後も変わらない（むしろ
    sleep 帰属への疑いが強まり、検証価値は上がった）。P1 成立の場合、効いた機構は SPEC の
    「負の回避」ではなく順序シグナル経由と解釈すべきことをここに事前登録する。P1 不成立の
    場合の「実装の敗北」第一容疑者は本項（飽和による信号消失）であり、§3.2 の再設計バリアント
    第 1 号は「SPEC 意味論に合わせた伝播（goal の吸収状態化・有向化・正規化のいずれか）」が
    自然な候補となる。

- **床効果**: 辞書ベース sleep 誘導（両群共通）が既に十分強い場合、グラフ伝播の追加寄与が小さく出る。その場合でも「検出できなかった」と正直に記録する（辞書誘導を切った追加実験は別途事前登録）。
- **実行時間**: v6_perseed は同設定（max_hops=15, sp-cand-topk=5）で 60 シード完走の実績あり。2 条件 × 30 シードは同規模。1 シードあたりの実測時間を FROZEN 前に 1 シードのパイロット（seed=100、解析から除外）で確認し、ここに追記する。
  - **パイロット実測（2026-07-02 追記）**: seed=100 で on 981s + off 1077s = **約 34 分/ペア → 30 ペアで約 17 時間（逐次）**。off の方が遅いのは孤立ノード除去が入らずグラフが大きいままのため（継承エッジ数 on 570 / off 758）。seed=100 は両条件とも warmup/eval FAIL の難シード（解析対象外なので問題なし）。装置検証: `inherited_propagated_nodes` on=659 / off=0（P3 操作チェック機構が実データで機能）、**warmup の paired 差 = 0**（同一シードの warmup は決定的に同一 = sleep 前に分岐が存在しないことの確認）、解析スクリプト `analyze_sleep_ablation.py` は実データで全経路（打ち切り・縮退 Wilcoxon・no-discordant McNemar）の動作を確認済み。
- **v6_perseed との非同一性**: 本実験の sleep-on は v6_perseed の extended 群の再現を兼ねるが、コード改変（フラグ追加・メタ記録追加）後の実行なので、数値の完全一致は保証されない。方向の一致（成功率 ≈ 95%、ステップ短縮）を再現性チェックとして報告する。
- **一般化**: 25×25 DFS 迷路 1 スケールのみの結果であり、スケール一般性は主張しない（51×51 への拡張は将来の別登録）。
