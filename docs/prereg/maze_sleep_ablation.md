# 事前登録: 迷路 stage-2 — Sleep 単独アブレーション（sleep on/off）

> **日付**: 2026-07-02（実験実施前にコミット）
> **状態**: DRAFT — シード数と実行時間見積もりを確定したら FROZEN に変更し、以後は追記のみ（本文の書き換え禁止）
> **前提**: v6_perseed（25×25）で成功率 71.9%→95.3%、平均ステップ −41%、エッジ −34% を観測。ただしこれは **10D ベクトル＋sleep 伝播＋カリキュラムを同時に変えたパッケージ効果**であり（baseline n=32 / extended n=64 と標本も非対称）、sleep 単独の寄与は未分離（2026-06-10 監査で指摘された「アブレーション負債」）。
> **実験装置**: `--sleep-propagate {on,off}` フラグを 2026-07-02 に実装（`qhlib/cli.py`, `qhlib/models.py`, `run_experiment_query.py`）。off = Wake1 の生グラフを無変更で Wake2 に継承（報酬伝播なし・孤立ノード除去なし・dim9 は初期値のまま）。9×9 スモークで操作を確認済み: on → 継承 57 ノード全てに `propagated` 属性、off → 継承 140 ノード（生グラフ）で `propagated` 属性ゼロ。

## 1. 主張（検証対象）

> Sleep 相のグラフ再編（Q 学習様の報酬伝播 + 孤立ノード除去 + dim9 同期）は、10D ベクトルとカリキュラムを両群で固定した条件下で、**単独で**第 2 エピソード（Wake2）の探索性能を改善する。

## 2. 理論の事前予測（sleep 機構が実在の荷重を持つなら成り立つこと）

- **P1（Primary）**: Wake2（eval）ステップ数は sleep-on < sleep-off（同一シード・同一迷路の paired 比較で有意）
- **P2**: Wake2 成功率は sleep-on ≥ sleep-off（25×25 では成功率は天井にない: v6_perseed で eval 95.3% vs baseline 71.9%）
- **P3（操作チェック）**: sleep-on の継承グラフは `propagated` 属性を持ち、sleep-off はゼロ（結果 JSON の `curriculum.per_seed.*.inherited_propagated_nodes` で機械検証）

## 3. 反証条件（外れたら理論側の敗北として記録する）

| 条件 | 帰結 |
|------|------|
| P1 不成立（paired 差の CI95 が 0 を含む、または逆方向） | **v6_perseed の改善（+23.4pt / ステップ −41%）はカリキュラム・10D ベクトル由来であり、sleep 伝播機構は荷重を持たない**と記録する。Sleep-RAG（凍結中）は前提を失い、復帰させずに再設計へ回す。論文 stage-2 の主張から「sleep の寄与」を撤回し「グラフ持ち越し＋カリキュラムの効果」に縮約する |
| P1 成立だが P2 逆方向（成功率が有意に低下） | sleep は速度と引き換えに堅牢性を損なうと記録し、主張を「ステップ短縮のみ」に縮約する |
| P3 不成立 | 実験装置の故障。結果を無効とし、修理後に再実行（これは理論の敗北ではなく装置の敗北として区別する） |

事後説明による矛盾吸収は行わない。予測が外れた場合は本ファイルに「敗北記録」を追記する。
「off 群は孤立ノードのせいで不利だった」等の言い訳を**事後に**導入することは禁止（孤立ノード除去は sleep の仕事の一部であり、その利得は sleep の利得である。伝播と掃除の寄与分解は本実験の範囲外で、別途事前登録の上で `--sleep-propagate-iters 0` により行う）。

## 4. 実験設計

### 条件（操作は 1 変数のみ）

| | sleep-on | sleep-off |
|---|---|---|
| `--sleep-propagate` | `on` | `off` |
| それ以外の全フラグ | 完全に同一 | 完全に同一 |

### 共通設定（v6_perseed の COMMON_ARGS + extended を両群に固定）

```
--maze-size 25 --max-steps 500 --max-hops 15 --sp-cand-topk 5
--curriculum-warmup-steps 500 --lambda-weight 0.01 --steps-ultra-light
--vector-mode extended
```

- 辞書ベースの sleep 誘導（sleep_plan / sleep_q、`--sleep-guide` デフォルト = override）は**両群で共通に動作**する。本実験が分離するのは**グラフ報酬伝播（graph-persistent DG）の寄与のみ**。
- **設計計画との対応**: `graph_persistent_dg/SPEC.md` §6 Phase 2 は 4 条件アブレーション（グラフ伝播 / 辞書β / 両方 / なし）を構想している。本実験はそのうち**「両方 vs 辞書βのみ」の 1 ペア**であり、README の最優先実験定義「sleep 伝播のみ切替」と一致する。残る 2 条件（伝播単独・両方なし）は本実験の結果を見て別途事前登録する（特に §6 の床効果リスクが現実化した場合、辞書βを切った「伝播単独 vs なし」が次の切り分けになる）。
- 報酬テーブルは実装値（goal +1.0 / novel +0.2 / revisit −0.4 / deadend −1.0 / blocked −1.0）を両群共通で使用。wake 中に dim8（生 reward）へ同期されるため、**off 群でも生報酬情報はベクトルに保持される** — sleep が加えるのは伝播値（dim9）・孤立ノード除去のみであり、これが分離対象の操作である。
- シード: **0–29（n=30、paired）**。シードが迷路と初期条件を決定するため、同一シードの on/off が対応のあるペアを成す。
- 実行順: シードごとに on → off を続けて実行（環境ドリフトの群間偏りを防ぐ）。
- 実行スクリプト: `experiments/maze/run_sleep_ablation.sh`（run_v6_perseed.sh の 2 条件版、per-seed 実行でメモリ蓄積を回避）。

### 統計（変更禁止）

1. **Primary**: Wake2（eval）ステップ数の paired 差。Wilcoxon signed-rank（両側 α=0.05）+ paired bootstrap CI95。
   - **打ち切りの扱い（事前定義）**: 失敗シード（500 ステップ内にゴール未達）の eval ステップ数は **steps=500（上限値）として全 30 ペアで主解析**を行う。感度分析として「両条件とも成功したペアのみ」の解析を併記する。主判定は前者。
2. Secondary: Wake2 成功率の McNemar 検定（正確二項）、Wake2 最終エッジ数（`avg_edges`）、継承グラフのノード・エッジ数。
3. 多重比較: 主検定は P1 の 1 つのみ。P2 以下は探索的と明記。

**解析コードの事前固定**: 上記の統計は `experiments/maze/analyze_sleep_ablation.py` として実装し、**実験実行前にコミット**する（bootstrap 乱数シード 20260702 固定、判定は §3 の文言を機械的に出力）。合成データで打ち切り・欠損・操作チェックの全経路を検証済み。実行後にこのスクリプトを変更する場合は逸脱として記録する。

## 5. 主要指標（変更禁止）

1. **Primary**: 25×25・n=30 paired における Wake2 ステップ数の sleep-on − sleep-off 差（Wilcoxon p 値と bootstrap CI95）
2. Secondary: Wake2 成功率差（McNemar）、エッジ数差、（参考）warmup 側の指標に群差がないことの確認（warmup は sleep 前なので差があってはならない = 追加の操作チェック）

## 6. 既知のリスク

- **床効果**: 辞書ベース sleep 誘導（両群共通）が既に十分強い場合、グラフ伝播の追加寄与が小さく出る。その場合でも「検出できなかった」と正直に記録する（辞書誘導を切った追加実験は別途事前登録）。
- **実行時間**: v6_perseed は同設定（max_hops=15, sp-cand-topk=5）で 60 シード完走の実績あり。2 条件 × 30 シードは同規模。1 シードあたりの実測時間を FROZEN 前に 1 シードのパイロット（seed=100、解析から除外）で確認し、ここに追記する。
  - **パイロット実測（2026-07-02 追記）**: seed=100 で on 981s + off 1077s = **約 34 分/ペア → 30 ペアで約 17 時間（逐次）**。off の方が遅いのは孤立ノード除去が入らずグラフが大きいままのため（継承エッジ数 on 570 / off 758）。seed=100 は両条件とも warmup/eval FAIL の難シード（解析対象外なので問題なし）。装置検証: `inherited_propagated_nodes` on=659 / off=0（P3 操作チェック機構が実データで機能）、**warmup の paired 差 = 0**（同一シードの warmup は決定的に同一 = sleep 前に分岐が存在しないことの確認）、解析スクリプト `analyze_sleep_ablation.py` は実データで全経路（打ち切り・縮退 Wilcoxon・no-discordant McNemar）の動作を確認済み。
- **v6_perseed との非同一性**: 本実験の sleep-on は v6_perseed の extended 群の再現を兼ねるが、コード改変（フラグ追加・メタ記録追加）後の実行なので、数値の完全一致は保証されない。方向の一致（成功率 ≈ 95%、ステップ短縮）を再現性チェックとして報告する。
- **一般化**: 25×25 DFS 迷路 1 スケールのみの結果であり、スケール一般性は主張しない（51×51 への拡張は将来の別登録）。
