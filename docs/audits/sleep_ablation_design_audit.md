# 監査: sleep アブレーション実験は sleep をテストできる設計だったか

> **日付**: 2026-07-02（アブレーション敗北記録 [prereg §8](../prereg/maze_sleep_ablation.md) の直後、著者の指示による設計精査）
> **問い**: 著者の設計意図 —「ゴールと負例の伝播が T 字路・十字路でゴール向きの重み勾配を作り、
> 1 回目に到達しなかったトライでも到達可能性が上がる」— は、実装と実験プロトコルに正しく
> 引き継がれていたか。
> **分析**: 全 30 シードの迷路構造（layout 復元 + BFS 最短経路）× warmup/eval 実測、
> v6_perseed 全 96 ラン（baseline 32 / extended 64）の warmup→eval 遷移。
> **結論**: **引き継がれていなかった。** 迷路自体は適切（分岐・袋小路とも十分）だが、
> プロトコルと実装の 4 つの独立な理由により、伝播勾配が行動を変えうる状況が実験に存在しなかった。

---

## 1. 実装の現状定義（著者の問い①への回答）

### 報酬の記録
- 記録先: **direction node**（位置×方向）のノード属性 `reward`（`run_experiment_query.py` 報酬記録部）
- 値: goal +1.0 / novel +0.2 / revisit −0.4 / deadend・blocked −1.0
- **上書き方式**: 同じ direction node を複数回通ると**最後のイベントが勝つ**。
  novel（+0.2）だった正解経路も、バックトラックで再通行すると revisit（−0.4）に上書きされる。
  「ゴールに至る正しい道」の途中ノードが負の報酬を持ちうる。

### goal の伝播値
- goal 報酬 +1.0 は **warmup でゴールに到達した場合のみ**、ゴール位置の direction node に存在する。
  未到達 warmup のグラフには正の勾配源（+1.0）が**原理的に存在しない**。

### 負例の「伝播」
- `propagated(n) = reward(n) + γ·max(propagated(neighbor))` の **max 演算が負例の伝播を構造的に殺す**:
  負のノードは自分の propagated を下げるだけで、隣人は max を取るため**正の隣人が 1 つでもあれば
  負の情報は無視される**。負が伝播するのは「負のノードしか隣人がいない端点」のみ（SPEC §3.3 の
  一本道の袋小路例はまさにそれ）。実迷路の分岐（正の候補が常に並ぶ）では、著者の意図した
  「負例の伝播による袋小路方向の回避」は機能しない。
- さらに無向 max 伝播の相互強化により全ノードが正に飽和する
  （既報: `test/test_sleep_propagate_semantics.py`、goal 到達時 dead-end ですら +9.9、tanh 全ノード >0.999）。

## 2. 迷路構造は適切だった（著者の問い③への回答）

30 シードの layout 復元による実測:

| 指標 | 実測（30 迷路の平均） |
|---|---|
| T 字路（次数 3） | **13.5 個/迷路**（範囲 9–18） |
| 十字路（次数 4） | 0.2 個/迷路 |
| 袋小路セル | 14.6 個/迷路 |
| warmup の袋小路遭遇 | **平均 8.9 回**（範囲 0–19） |

**「袋小路を経験せずに一本道になった」迷路ではなかった。** 分岐は十分にあり、warmup は袋小路を
繰り返し踏んでいる。勾配選択をテストできる**場所**は迷路に存在した。問題は迷路ではない（§3）。

## 3. しかし勾配が行動を変えうる状況が存在しなかった（問い②への回答）

### 3.1 warmup 成功シード（23/30）: eval は既に理論最短 — 改善余地ゼロ

**23 シード全てで eval ステップ数 = BFS 理論最短経路長（比率 1.000、23/23 完全一致）。**
eval の袋小路遭遇は 23 ラン合計でわずか 4 回。
warmup 成功時は sleep_plan（BFS 計画）が `--sleep-guide override`（デフォルト）で行動を完全支配し、
理論最短をそのまま歩かせる。**1 歩も短縮の余地がなく、伝播値が読まれる幕がない。**
prereg §6 で「床効果リスク」と登録したものは、リスクではなく 100% の現実だった。

### 3.2 warmup 失敗シード（7/30）: 勾配源が存在しない

goal 報酬 +1.0 がグラフにないため、「ゴールに向かう重み勾配」は原理的に構築不能。
7 シードとも eval 失敗（例外は off 群 seed=23 の 1 件のみ = 伝播と無関係）。

### 3.3 決定的事実: v6_perseed の +23.4pt は Wake2 の改善ですらなかった

v6_perseed 全ランの warmup→eval 遷移を復元した結果:

| | n | eval 成功 | warmup 失敗 | **warmup失敗→eval成功（"lifted"）** |
|---|---|---|---|---|
| baseline (8D) | 32 | 23/32 = **71.9%** | 9 | **0** |
| extended (10D+sleep) | 64 | 61/64 = **95.3%** | 3 | **0** |

**eval 成功集合 = warmup 成功集合が両群で完全に一致**（lifted 0、dropped 0）。
つまり報告されてきた「71.9%→95.3%」は **Wake1（warmup）自体の探索成功率の差**であり、
sleep 相も Wake2 も一切関与していない。10D ベクトル（dim8 生報酬タグ）が **warmup 中の
dead-end 検出・探索を改善していた**（実装コミット e47829a の記述 "unified 10D vector for
AG-DG dead-end detection ... AG fires selectively at dead-ends" と完全に整合）。

**「Wake-Sleep-Wake で記憶グラフが次の試行を改善する」という物語は、
(i) sleep 伝播の寄与ゼロ（アブレーション）、(ii) 改善が Wake2 ですら起きていない（本監査）、
の二重の意味でデータに支持されていない。実効的な因果は
「10D が Wake1 の探索を改善 → Wake1 成功なら辞書誘導が Wake2 を最短化」である。**

## 4. 著者の設計意図をテスト可能にする再設計要件

意図「伝播勾配による分岐選択・未達トライの引き上げ」を検証するには、次の 4 条件を同時に満たす
必要がある（現行実験は 4 つとも欠けていた）:

| # | 要件 | 現行の欠落 | 再設計の選択肢 |
|---|---|---|---|
| R1 | eval の行動選択が伝播値を実際に読む | `--sleep-guide override` の辞書が支配 | `--sleep-guide off`（または prefer）で伝播 readout を主役に |
| R2 | 改善余地が存在する | eval が既に理論最短（23/23） | R1 で辞書を切れば eval は自力ナビになり余地が生まれる |
| R3 | 勾配源（goal 報酬）が存在する | warmup 失敗時は原理的に不在 | warmup を「到達直後に打ち切り」（到達するが経路は非効率）にする、または到達済みシードに限定した設計 |
| R4 | 伝播値に識別力がある | 飽和（tanh>0.999 一様）+ 負例が max で死ぬ | goal 吸収状態化／有向化／正規化。負例は max 伝播と根本的に不整合 — 別チャネル（エッジ通行コスト等）を検討 |

追加の従属変数候補: eval ステップの最短比だけでなく、**「warmup で踏んだ袋小路を eval で踏まない率」**
（勾配が効くなら最も直接的に現れる指標）。

これらは §3.2 の試行予算（N=2、各回事前登録必須）の設計入力である。
