# 螺旋的 AG-DG フローと L1 検索の再設計

**作成日**: 2026-02-10
**文脈**: Phase D 実験の結論から導出された構想

---

## 1. 発見: ヒューリスティックの限界

Phase D 実験（D-3〜D-6b）を通じて以下が判明した:

- q-beta=8 で −12.6% 改善（274.7 → 240.0 steps）
- しかしこれは **経験を重みに反映し、ルールベースで判断するヒューリスティック**
- F 値が自律制御しているのは DG スコア・グラフ構造・β₁ の 3 つのみ
- **行動選択に関わるパラメータはすべて手動設定**

q-beta は action-temp に統一して廃止したが、本質的な問題は
「F 値のパイプラインがグラフ構築で止まり、行動選択まで届いていない」こと。

---

## 2. 核心的洞察: タスクが検索クエリになる

人間が「迷路を解け」と言われたとき:

```
タスク設定: "迷路を解け"
    ↓ （自動的に想起）
正例: goal に至る経験
負例: 行き止まり、ぐるぐる回った経験
    ↓
記憶を検索して、正例を活かし負例を避ける行動を選ぶ
```

**タスクの設定そのものが、正例/負例の定義を駆動する。**
報酬値のハードコード（goal=+1.0, revisit=-0.4）は人間がやっていることの代行に過ぎない。

DG はまさに「そのタスクにとって情報量が高いもの」を測る尺度。
DG が高い辺 = タスクにとって重要な情報。
**DG グラフを検索して正例に至るパスを見つけるのが L1 の仕事**、という整理ができる。

---

## 3. 螺旋的 AG-DG フロー

L1 の検索は AG-DG フローの **外部モジュール** ではなく **内側** に位置する。

```
AG 発火（注意: 何か変わった）
  ↓
DG 計算（情報利得: どれくらい重要か）
  ↓
  ├─ エッジ生成 → グラフ成長
  │
  └─ L1 検索（DG グラフから正例/負例を探す）
       ↓
     行動選択
       ↓
     新しい経験 → AG 発火 → ...
```

WSW サイクルを重ねるたびに:
- 1周目: 粗いグラフ → 粗い検索 → 粗い判断
- 2周目: goal-start エッジ追加 → 正例が見える → 判断改善
- 3周目: さらに精緻化 → ...

**同じ AG → DG → 検索 → 行動 のループを、解像度を上げながら繰り返す。**
これが螺旋。グラフが平面的に広がるのではなく、同じ構造の上に深さが積み重なる。

本来は Sleep フェーズを待たず、**1 ステップごとに螺旋が回る** —
AG が発火するたびに DG グラフが更新され、L1 の検索結果が変わり、行動が変わる。

---

## 4. L1 フローの再設計案

### 4.1 二つの attention

| attention | 意味 | 駆動力 |
|-----------|------|--------|
| 類似度 attention | 今見ているものとの関連度 | ベクトル距離 |
| DG attention | その辺のタスクにとっての情報価値 | geDIG スコア |

### 4.2 ループの正例/負例判定

グラフインデックスサーチでヒットしたノードからローカルループを探索し、
そのループの性質で判断する:

- **正例ループ**: goal を含む、propagated 値が高いノードを含む → 帰還経路が存在
- **負例ループ**: 同じ場所の繰り返し、行き止まりへの往復 → 探索の無駄

β₁ は「ループが何個あるか」を測るが、ここでは「そのループがどんな性質か」を見る。

### 4.3 フォールバック条件

この枠組みではフォールバック条件が自然に導出される:

| L1 の結果 | 判断 |
|-----------|------|
| 正例ループ発見 | L1 で判断完了 → そのパス方向に進む |
| ループ発見だが全て負例 | L2 にフォールバック（既知だが行き詰まり） |
| ループなし | L2 にフォールバック（未知領域、グラフが疎） |

**「正例ループの有無」がフォールバック条件になる。**

### 4.4 goal-start DG エッジ

goal 到達時に goal↔start 間に DG エッジを貼る:

- **長距離の情報経路**が生まれる（現在はグラフが近傍ノード間のみ）
- 次の episode で start 付近から既に「goal 方向」の情報が見える
- ループ判定でも goal を含むループが検出しやすくなる
- 「迷路を解いた」という経験そのものの DG 的記録

経路上の要所（分岐点）にも中継エッジを貼ることで、
局所的な判断にも goal 方向の情報が伝わる。

## 5. Phase ロードマップとの接続

README の Phase テーブル:

| Phase | 正例/負例 | 埋め込み空間 |
|-------|----------|-------------|
| 1 | なし | ヒューリスティック |
| 2 | ヒューリスティック | ヒューリスティック |
| 3 | ヒューリスティック | 内発報酬により可変 |
| 4 | **経験により可変定義** | 内発報酬により可変 |

### 螺旋 AG-DG フローが示す Phase 3→4 への道筋

**Phase 3（埋め込みの自律化）:**
螺旋の各周回で DG グラフが更新されるということは、
ノードのベクトル表現（埋め込み）が経験に応じて変化するということ。
DG スコアが高い辺の周辺ノードは「重要」とマークされ、
それ自体が埋め込み空間の再構成に相当する。

現在の 10D ベクトル（dims 8-9: reward, propagated）の reward/propagated 値は
Sleep で更新されるが、これを螺旋の各ステップで即時更新すれば、
**埋め込みが DG 駆動で自律的に変化する**構造になる。

**Phase 4（正例/負例の自律判定）:**
タスク（「迷路を解け」）が正例/負例を定義するという洞察は、
Phase 4 の「経験により可変定義」に直結する。

- 最初は何が正例か分からない（Phase 1）
- goal に到達した経験が蓄積される → goal-start エッジが生成される
- このエッジの DG スコアが高い = **経験から「goal 到達は正例」と判定された**
- 行き止まりの繰り返しは DG スコアが低い（情報利得ゼロ）= **負例と判定された**

つまり **DG スコアそのものが正例/負例の判定関数** になり得る。
報酬値をハードコードする必要がなくなる。

### まとめ: 螺旋が Phase 遷移を駆動する

```
Phase 1: AG-DG フローでグラフを構築（正例/負例なし）
    ↓ goal 到達経験
Phase 2: goal-start エッジ生成 → DG が正例/負例を暗黙的に区別
    ↓ 螺旋の繰り返し
Phase 3: DG 駆動で埋め込みが自律変化（propagated の即時更新）
    ↓ ループ判定の導入
Phase 4: 正例/負例の判定が DG スコアから自動導出される
```

Phase 間の遷移は設計の切り替えではなく、
**螺旋の深化によって自然に起きる**。

## 6. ミクロレベルへの分解: 壁衝突と進行可否

螺旋 AG-DG フローはマクロな経路選択（goal 方向 vs 行き止まり）だけでなく、
**ミクロな物理的制約の学習**にも同じ構造が適用できる。

### 6.1 壁への衝突

現在の実装では壁衝突は `possible_moves` のフィルタで処理される（ルールベース）。
しかし本来、「北に進もうとしたが壁で進めなかった」は:

- AG 発火: 行動の結果が予測と異なった（注意イベント）
- DG 計算: 「北=壁」という情報は情報利得が高い（環境の制約を発見）
- グラフ更新: その方向ノードに「blocked」属性が付与される
- 次回の L1 検索: 同じ位置での負例として検出 → その方向を避ける

つまり **壁の存在を事前に知らなくても、衝突経験から DG 的に学習できる**。

### 6.2 進行可能性

同様に「南に進んだら新しい通路があった」は:

- AG 発火: 新しい空間を発見
- DG 計算: 高い情報利得（未知→既知の遷移）
- グラフ更新: 新しいエッジが生成される
- 次回の L1 検索: 正例として蓄積 → 探索の候補に

### 6.3 現在のハードコードとの対応

| 現在（ハードコード） | 螺旋 AG-DG（学習） |
|-------------------|-------------------|
| `possible_moves` でフィルタ | 壁衝突 → AG 発火 → DG が blocked を学習 |
| `reward=-1.0` (blocked) | DG スコアが低い = 負例 |
| `reward=+0.2` (novel) | DG スコアが高い = 正例 |
| `reward=-0.4` (revisit) | DG スコアゼロ（情報利得なし）= 負例 |
| `reward=-1.0` (deadend) | ループ判定で負例ループ検出 |

**reward 値のハードコードは、DG が自然に導出するスコアの近似に過ぎない。**

マクロ（goal/行き止まりの経路選択）もミクロ（壁/通路の物理制約）も、
同じ AG → DG → 検索 → 行動 の螺旋で統一的に扱える。
これが「正例/負例の自律判定」の具体的な意味。
