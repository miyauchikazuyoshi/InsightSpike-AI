## 1. エピソードベクトルの構造：特徴 vs ラベル

### 1.1 8次元ベクトルの再解釈

```
8次元ベクトル
├── 構造特徴（類似度計算の本体）
│   ├── [0] row      位置
│   ├── [1] col      位置
│   ├── [2] dx       方向
│   ├── [3] dy       方向
│   ├── [4] passable 通過可能性
│   └── [5] visits   訪問回数
│
└── ラベル（付随する評価情報）
    ├── [6] outcome  良い/悪い（旧 success）
    └── [7] purpose  目的との関係（旧 is_goal）
```

### 1.2 検索と評価の分離

```
similarity = f(構造特徴)     ← 「どれが近いか」
confidence = f(ラベル)       ← 「良かったか悪かったか」

score = similarity × confidence
```

ベクトル空間での検索と、ラベルによる評価を分離することで、設計がクリーンになる。

## 2. ラベルの抽象化：purpose（目的）

### 2.1 具体から抽象へ

```
is_goal (迷路)     → purpose (一般)
「ゴール座標か」    → 「目的に寄与するか」

※ purpose は「目的そのもの」ではなく、**目的に対する評価ラベル**として扱う前提。
```

### 2.2 ドメインへの写像

| ドメイン | purpose の意味 |
|----------|----------------|
| 迷路 | ゴール座標への遷移 |
| ARC | 正解パターンを生成する変換 |
| RAG | 良い回答を導くドキュメント |
| 一般 | **目的達成に寄与するエピソード** |

### 2.3 geDIG との接続

```
F = ΔEPC − λ·ΔIG

ΔIG = 「目的に対する情報利得」
    = 「purpose=1 のノードにどれだけ近づいたか」
    （これは **概念上の近似**。現実装のIG定義とは完全一致しない）
```

purpose を明示的に持つことで、ΔIG の計算が「目的関数」として定義可能になる。
ただし現時点では **ヒューリスティック設計**であり、厳密な理論化は今後の課題。

### 2.4 Phase 5（ひらめき）への道筋

```
既存の purpose に対する経路を見つける = 理解（エッジ操作）
新しい purpose を生成する           = ひらめき（ノード生成）
```

## 3. ノードの粒度：(s,a) vs (s,a,s')

### 3.1 意図 vs 経験

```
(s, a)     = 「意図」（何をしようとしたか）
(s, a, s') = 「経験」（実際に何が起きたか）
```

### 3.2 決定論的 vs 非決定論的

| 環境 | 特徴 | ノード設計 |
|------|------|------------|
| 決定論的（迷路） | (s,a) → s' が一意 | (s,a) で十分、s' は属性 |
| 非決定論的（実世界） | 同じ (s,a) から異なる s' | (s,a,s') が必要 |

### 3.3 意味空間の自律化との関係

Phase 3（状態表現の自律化）では、「何を同一視するか」を学習する。

- (s,a) で同一視するか、(s,a,s') で区別するかは、タスクによって変わる
- これを自律的に決められるようになるのが理想
- F（コスト vs 情報利得）で最適な粒度が決まる

## 4. GPT的 vs BERT的タスク構造

### 4.1 根本的な違い

```
┌─────────────────────────────────────────────────┐
│ GPT的（自己回帰）                               │
│   過去 → 未来を予測                             │
│   (s, a) → s'                                   │
│   例：迷路、ゲーム、時系列予測                  │
│                                                 │
├─────────────────────────────────────────────────┤
│ BERT的（双方向・穴埋め）                        │
│   文脈から中間を推論                            │
│   (s, s') → a                                   │
│   例：ARC、アナロジー、関係推論                 │
└─────────────────────────────────────────────────┘
```

※ これは **比喩的整理**。現実のタスクは両者の混合であり、ARC も両方の性質を持ちうる。

### 4.2 何が既知で何が未知か

| | 迷路（GPT的） | ARC（BERT的） |
|---|---|---|
| 既知 | (s, a) 状態と行動 | (s, s') 入力と出力 |
| 未知 | s' 結果 | a 変換 |
| タスク | s' を予測/到達 | a を発見 |

### 4.3 ARC = マスク言語モデル

```
BERT:
  入力: [A] [MASK] [B]
  タスク: [MASK] を予測

ARC:
  入力: [input] [?] [output]
  タスク: [?] (transform) を予測
```

### 4.4 意味空間への影響

```
GPT的:
  埋め込み = 因果的・時系列的
  エッジの方向が重要
  「この後どうなる？」

BERT的:
  埋め込み = 対称的・関係的
  ノード間の対応が重要
  「この間に何がある？」
```

### 4.5 geDIG での対応

```
GPT的タスク（迷路）:
  F = 遷移のコスト - 到達の利得
  エッジを辿る探索
  Phase 1-4 で対応可能

BERT的タスク（ARC）:
  F = 変換のコスト - 適合の利得
  マスクを埋める探索
  Phase 4-5 の領域（仮説生成）
```

### 4.6 DSL が ARC を Phase 2-3 に落とす理由

```
a（変換）の候補 = DSL の組み合わせ（有限）
        ↓
「生成」ではなく「探索」で済む
        ↓
Phase 5（仮説ノード生成）に行かずに済む
```

## 5. 統一的な視点

### 5.1 どちらも「構造の発見」

```
GPT: s → [a] → s' → [a'] → s'' ...
     行動の系列を発見

BERT: s ←[a]→ s'
      関係（変換）を発見
```

### 5.2 geDIG は両方に適用可能

```
F = ΔEPC - λ·ΔIG
  = 構造コスト - 説明力

GPT的: 遷移系列の最小コスト経路
BERT的: 変換仮説の最小コスト説明
```

### 5.3 LLM アーキテクチャへの示唆

タスクの性質（GPT的 vs BERT的）によって、最適な意味空間の構造が変わる可能性がある。

geDIG がアーキテクチャ選択（因果的 vs 双方向）にも指針を与えられるかもしれない。

## 6. DG の役割の明確化

### 6.1 DG ≠ 正例ラベル

```
DG = 構造の記憶強化（関連づけ）
   ≠ 正例/負例のラベル

DGで確定されたエッジ = 「この遷移とこの遷移は関連がある」
接続先が良いか悪いかは outcome ラベルで別管理
```

### 6.2 「嫌な予感」の実現

```
2回目の走破時：

現在地: 分岐点A
     ↓
 類似検索で「分岐点Aでの遷移」ノードが想起
     ↓
 そのノードの outcome ラベルを見る
     ↓
 outcome = -1（行き止まりだった）
     ↓
 「この方向はまずい」という予感
     ↓
 別の方向を選ぶ
```

グラフを深く辿る必要がないケースもある。ノードの構造特徴で検索し、ラベルで評価する。

---

## 7. 今後の視点として

1. **purpose の抽象化**が Phase 1-5 を貫く軸になる
2. **(s,a) vs (s,a,s')** の粒度選択は意味空間の自律化の核心的問い
3. **GPT的 vs BERT的**の対比が、タスク分類と最適アーキテクチャ選択に使える
4. **DSL による有限化**が、BERT的タスクを Phase 2-3 に落とす鍵
