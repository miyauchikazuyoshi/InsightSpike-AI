# BRIGHT β₀-Adaptive Re-retrieval 実験レポート

**日付**: 2026-03-11
**実験ID**: v12 BRIGHT Spec B+C
**担当**: InsightSpike-AI

---

## 1. エグゼクティブサマリー

Spec A (CoT Re-retrieval) の成功を受け、グラフ連結性 (pre-β₀) を事前計算し、
クエリ難易度に応じて Re-retrieval の強度を **3ティア適応ルーティング** で制御する手法を実装・評価した。

**結果**: nDCG@10 = **0.1596** (Spec A: 0.1520, +5.0%)。
BM25 ベースラインからは **+134.3%**。ただし全体の改善は統計的に有意ではない (p=0.468)。

**ドメイン別では明暗が分かれた**:
- Biology: **+25.5% (p=0.039 ★★)** — 攻撃的 Re-retrieval が大きく奏功
- Economics: -1.3% (n.s.) — ほぼ横ばい
- StackOverflow: -15.1% (n.s.) — CoT スキップによる損失

**主要発見**: Tier 3 (攻撃的 Re-retrieval) は Spec A 比 +0.031 nDCG (p=0.068) と有望。
一方 Tier 1 (CoT スキップ) のコスト削減効果は限定的 (15%) で、nDCG を微減させる。
pre-β₀ の分布がドメインで大きく異なり、ドメイン非依存の固定閾値は最適ではない。

## 2. 背景

### 2.1 Spec A の成果と課題

Spec A (CoT Re-retrieval) で nDCG@10 = 0.1520 (+24.7% vs CoT+Graph) を達成。
β₀ 相関分析により、グラフ連結性が Re-retrieval 効果と強く相関することを発見:

| β₀ グループ (post-CoT) | CoT+Graph | CoT Re-ret | Δ nDCG | Gold 発見率 |
|------------------------|-----------|------------|--------|-----------|
| ≤3 (高連結) | 0.140 | 0.150 | +0.010 | 26% |
| 4-10 (中程度) | 0.115 | 0.165 | +0.051 | 34% |
| >10 (断片的) | 0.031 | 0.127 | **+0.097** | **45%** |

### 2.2 アプローチ

β₀ を **CoT 生成前に事前計算** (pre-β₀) し、3ティア適応ルーティングでリソース配分を最適化:

- **Tier 1** (pre-β₀ ≤ 3): 高連結 → CoT スキップ (グラフのみ) → LLM コスト削減
- **Tier 2** (3 < pre-β₀ ≤ 10): 中程度 → 標準 CoT + Re-retrieval (50 docs, 20 concepts)
- **Tier 3** (pre-β₀ > 10): 断片的 → 攻撃的 Re-retrieval (100 docs, 40 concepts)

## 3. 手法

### 3.1 パイプライン

```
[Adaptive Re-retrieval パイプライン]
Phase 1:   BM25(query) → top-100
Phase 1.5: pre-graph → pre-β₀ → ルーティング判定       ★新規
Phase 2:   CoT 生成 (Tier 1 はスキップ)                  ★条件分岐
Phase 2.5: BM25(CoT concepts) → Re-retrieval             ★強度分岐
           Tier 2: top_k=50,  concepts=20, graph_slots=10
           Tier 3: top_k=100, concepts=40, graph_slots=16
Phase 3:   Graph 構築 (merged candidates)
Phase 4:   CoT ノード注入 (Tier 1 はスキップ)
Phase 5-6: Graph scoring → Combined re-rank
```

### 3.2 pre-β₀ 計算

BM25 top-k の文書からエンティティグラフを構築し、連結成分数 (β₀) を計算。
LLM 呼び出し不要、インメモリ計算 (<100ms)。
pre-β₀ は CoT 注入前のため、post-CoT β₀ より一般に高い値を取る。

### 3.3 パラメータ

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| beta_low | 3 | Tier 1/2 境界 |
| beta_high | 10 | Tier 2/3 境界 |
| cot_retrieval_top_k | 50 (T2) / 100 (T3) | Re-retrieval 文書数 |
| cot_retrieval_max_concepts | 20 (T2) / 40 (T3) | BM25 クエリ概念数 |
| graph_top_k | 50 | グラフ構築文書数 |
| graph CoT slots | 10 (T2) / 16 (T3) | グラフ内 CoT 文書枠 |
| rerank_alpha | 0.1 | BM25 vs Graph 重み |
| model | gpt-4o-mini | CoT 生成モデル |

## 8. なぜ Biology で効果的か — メカニズム分析

### 8.1 ドメイン特性と pre-β₀

Biology のエンティティグラフは高度に断片的 (mean pre-β₀ = 18.5):
- 各文書が独立した生物学的トピック (phototaxis, genome, immunity, ...) を扱う
- BM25 top-50 文書間のエンティティ共有が少ない → 多数の連結成分

→ Tier 3 (攻撃的) にルーティング → **100 文書 + 40 概念** で語彙ギャップを広範に橋渡し
→ Gold 発見率 51.5% (Spec A の 34.0% から大幅向上)

### 8.2 StackOverflow の課題

StackOverflow のエンティティグラフは密結合 (mean pre-β₀ = 5.9):
- コード関連エンティティ (Python, DataFrame, JSON, ...) が多くの文書で共有
- pre-β₀ ≤ 3 が 38.5% → Tier 1 (CoT スキップ)
- しかし CoT は語彙ギャップ橋渡しに依然として有効 → スキップで損失

### 8.3 根本的知見

**pre-β₀ と post-CoT β₀ は異なるシグナル**:
- pre-β₀ はグラフ密度の指標 (ドメイン依存)
- post-CoT β₀ はクエリ難易度の指標 (CoT がどれだけ橋渡ししたか)
- 固定閾値 (beta_low=3, beta_high=10) はドメイン間で最適ではない

## 11. nDCG=0 クエリの失敗分析

206/323 (63.8%) のクエリが nDCG=0 のまま残っている。これらの失敗パターンを分析した。

### 11.1 失敗の根本原因 — 3分類

| 原因 | 件数 | 割合 | 説明 |
|------|------|------|------|
| **C) 候補プール不足** | 122 | **59.2%** | CoT Re-retrieval でも gold 文書がプールに入らない |
| **B) Rerank 失敗** | 45 | 21.8% | Gold を候補に含むが top-10 に浮上できない |
| **A) CoT スキップ損失** | 39 | 18.9% | Tier 1 で CoT をスキップし機会を逃した |

**最大の失敗要因は「候補プール不足」(59.2%)**。
BM25 top-100 + CoT Re-retrieval 50〜100 でも gold 文書を発見できない。
これは BM25 の語彙一致ベースの限界を示す。

### 11.2 失敗要因の詳細

#### C) 候補プール不足 (122件, 59.2%)

BM25 は単語一致検索のため、クエリと gold 文書の間の語彙ギャップが深い場合に機能しない。
CoT が専門用語を生成しても、1.33M 文書コーパス中で BM25 top-100+α に関連文書が入らない。

- 例: *"Why do mints make your mouth feel cold?"* → gold 文書は TRPM8 受容体やメントールの薬理学を扱う
- CoT が "TRPM8", "menthol receptor" を生成しても、BM25 の tf-idf では不十分
- **Gold 文書数が少ないほど困難**: gold≤1 で成功率 22.2%, gold≥11 で 57.1%

| Gold 文書数 | クエリ数 | 成功率 |
|------------|---------|--------|
| ≤1 | 81 | 22.2% |
| 2-3 | 125 | 28.8% |
| 4-10 | 89 | 52.8% |
| ≥11 | 28 | 57.1% |

gold 文書が多いほど「当たりやすい」。少ない場合は BM25 の語彙ギャップを超えられない。

#### B) Rerank 失敗 (45件, 21.8%)

Gold 文書を CoT Re-retrieval で発見したにもかかわらず、graph scoring で top-10 に浮上できない。
45 件すべてで `gold_hits_top10 = 0`。

- 例: *"Insects attracted to light"* → phototaxis 関連文書を発見したが graph で低スコア
- 例: *"Why doesn't water enter my body through my anus?"* → 新規 gold=2 を発見、いずれも top-10 外
- **Graph scoring の限界**: エンティティ共起ベースのため、概念的関連は捉えにくい

#### A) CoT スキップ損失 (39件, 18.9%)

Tier 1 (pre-β₀ ≤ 3) で CoT をスキップした 49 クエリ中 39 が失敗 (79.6%)。
CoT ありの Tier 2+3 の失敗率は 60.9%。

- **StackOverflow が突出**: 失敗 39 件中 36 件が SO
- SO はコード関連エンティティ (Python, DataFrame, JSON) が共有されグラフが密結合 → pre-β₀ が低い → Tier 1 へ
- しかし実際は語彙ギャップが存在: 例 *"melt command in Snowflake"* は専門用語で CoT が有効なはず

### 11.3 成功クエリとの比較

| 指標 | nDCG=0 (206q) | nDCG>0 (117q) | 倍率 |
|------|---------------|---------------|------|
| 平均 gold 文書数 | 3.9 | **7.2** | 1.8x |
| CoT 新規 gold 発見数 | 0.3 | **1.4** | 4.5x |
| CoT スキップ率 | 18.9% | 8.5% | 2.2x |
| クエリ長 (words) | 34 | 34 | 1.0x |

**クエリ長に差はない**。Gold 文書数と CoT Re-retrieval の有効性が成否を決定する。

### 11.4 ドメイン別失敗パターン

| Domain | nDCG=0 | 失敗率 | T1失敗 | T2失敗 | T3失敗 | 主要要因 |
|--------|--------|--------|--------|--------|--------|---------|
| biology | 55 | 53.4% | 1 | 9 | 45 | 候補プール不足 |
| economics | 69 | 67.0% | 2 | 21 | 46 | 候補プール不足 |
| stackoverflow | 82 | 70.1% | **36** | 34 | 12 | **CoT スキップ + 候補不足** |

- **Biology**: ほぼ全て Tier 3 (AGG) → 攻撃的 Re-retrieval でも足りない。エンティティグラフが断片的すぎる。
- **Economics**: Tier 2/3 が主流だが、経済理論の抽象的な語彙ギャップが深い。
- **StackOverflow**: Tier 1 スキップが最大の問題 (36/82 = 44%)。コード系の密結合グラフが誤ルーティングを誘発。

### 11.5 次のステップへの示唆

| 失敗原因 | 対策 | 期待救済数 |
|---------|------|-----------|
| A) CoT スキップ (39件) | **Spec D: 全クエリ攻撃的** | ~15-20件 |
| B) Rerank 失敗 (45件) | Graph scoring 改善 / LLM-based rerank | ~20-30件 |
| C) 候補プール不足 (122件) | **Dense retrieval 導入** (E5, BGE等) | ~40-60件 |

**最大のレバレッジは Dense retrieval の導入** (原因 C の 122 件に対処)。
BM25 の語彙一致の限界を超えるには、意味ベースのベクトル検索が必要。
ただしコスト・インフラの変更が大きいため、まず Spec D (全クエリ攻撃的) で
原因 A の 39 件を低コストで救済するのが合理的。

## 12. 限界と次のステップ

### 12.1 本実験の限界

1. **全体の改善が統計的に有意でない** (p=0.468): ドメイン間の効果の打ち消し合い
2. **StackOverflow での低下**: 固定閾値の Tier 1 スキップが有害
3. **pre-β₀ とクエリ難易度の対応が不完全**: ドメイン特性に強く依存
4. **コスト削減が限定的**: 15% ($0.9) は投資対効果として小さい

### 12.2 Tier 3 (攻撃的 Re-retrieval) の検証

Tier 3 は全ドメインで Spec A を上回った (Δ = +0.031, p=0.068)。
**Tier 1 スキップを無効化し、全クエリに攻撃的 Re-retrieval を適用** すれば、
Spec A をさらに上回る可能性が高い:

| 仮説 | 設定 | 期待効果 |
|------|------|---------|
| aggressive-only | 全クエリに top_k=100, concepts=40 | nDCG > 0.160 |
| adaptive-v2 | ドメイン適応閾値 | SO の低下を回避 |

### 12.3 次の仕様候補

| # | 仕様 | 概要 | 優先度 |
|---|------|------|--------|
| D | Aggressive-only | Tier 1 スキップ廃止、全クエリ攻撃的 Re-retrieval | ★★★ |
| E | Query Decomposition | 複合クエリを部分クエリに分解 → 各部分で BM25 検索 | ★★★ |
| F | Domain-adaptive β₀ | ドメインごとに閾値を学習 | ★★ |
| G | Iterative CoT | CoT → Re-retrieve → 新文書で CoT → Re-retrieve の反復 | ★★ |

## 13. 結論

β₀-Adaptive Re-retrieval は、Tier 3 (攻撃的 Re-retrieval) による候補プール拡大が有効であることを実証した。
特に biology ドメインでは +25.5% (p=0.039) の統計的に有意な改善を達成。
一方、Tier 1 (CoT スキップ) はコスト削減効果が限定的 (15%) で、
StackOverflow のようにエンティティグラフが密なドメインでは逆効果。

**主要な教訓**:
1. **攻撃的 Re-retrieval (100 docs, 40 concepts) は有効** — Tier 3 は全ドメインで改善
2. **CoT スキップは慎重に** — pre-β₀ はドメイン依存で、固定閾値は不適切
3. **pre-β₀ ≠ クエリ難易度** — グラフ密度はドメイン特性を反映するが、CoT の必要性とは異なるシグナル

BM25 (6.8) → Graph (10.8) → CoT+G (12.2) → CoT Re-ret (15.2) → Adaptive (16.0) と、
5ステップの着実な改善で BM25 から +134% に到達。
次のステップとして、攻撃的 Re-retrieval の全クエリ適用 (Spec D) を推奨する。
